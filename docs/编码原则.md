# 编码原则

| 原则 | 做法 | 验收问题 |
|---|---|---|
| 编码前思考 | 说明假设、依据、权衡和未知；重大歧义先澄清 | 是否把候选能力当成既成事实？ |
| 简洁优先 | 只写当前需要的接口与实现，不铺插件市场或通用引擎 | 是否能删掉一层仍满足当前需求？ |
| 精准修改 | 按任务改动；保留用户工作和既有行为 | 每行变更能否对应需求或缺陷？ |
| 目标驱动执行 | 为竞态、权限边界和协议错误定义可验证行为 | 是否有明确失败用例和结果证据？ |

测试按风险选择：协议与生命周期要测试；文案和说明不用形式化重复实现的测试。类型检查、模拟单测、真实适配器验证、桌面视觉验收分别报告。

任务开始写三步以内的计划：改什么、如何验证、何时算完成。完成后更新该目录 backlog 与 docs/实时进度.md。不得用“能启动”替代调试正确性。
