# 调试能力与运行时画布设计

更新：2026-10-23。状态：**设计与排期，未实现**。本文件回答两件事：调试怎样追平 VSCode；运行时画布怎样从“变量卡片列表”变成“函数框 + 数据流 + 循环轨道”。卡片尺寸和渲染边界另见 [canvas-card-spec.md](canvas-card-spec.md)。

## 结论

- 调试先按 **DAP 能力矩阵**补齐；适配器不提供的能力必须置灰并说明，不伪造 VSCode 效果。
- 运行时画布的核心不是“把变量摆得更好看”，而是把代码世界的关系一对一站到画布上：**函数/栈帧是容器，变量是容器里的实体，赋值/读取/迭代是带标签的边，循环是轨道，历史帧是时间轴**。
- 任何会执行用户代码的能力（Watch、REPL、条件断点、张量元数据求值）都必须经过显式授权，并受 `sessionId/runId/stopEpoch` 代际校验。
- 变量值只在 DAP 停点或记录帧采集；不把“运行中某瞬间的值”伪造成实时监控。

## 现状差距（已对照代码核实）

| 能力 | 现状 | 具体问题 |
|---|---|---|
| 变量树 | 启动时一次性抓取 `Locals` | `MAX_VALUES=500`、`MAX_DEPTH=3`；子项固定 `start=0,count=100`；没有 `namedVariables/indexedVariables` 计数、没有分页、没有“加载更多”；UI 只渲染前 100 个子项，长数组被静默截断 |
| 作用域 | 只读 `Locals` | 没有 `Globals/Closure/Special` 分组、过滤和排序；`<module>` 帧被跳过 |
| Watch | 不存在 | `evaluate` capability 固定为 `false`，Host 没有 `debug.evaluate`，Inspector 没有监视区 |
| 调试控制台 | 只有输出 | REPL 明确标注未启用；不能输入表达式求值 |
| 断点 | 只有行断点，启动时下发 | 没有条件、命中次数、日志断点、异常断点；运行中不能更新 |
| 改变量 | 不存在 | Host 没有 `setVariable` 方法，UI 不能编辑变量值 |
| 线程/栈 | 只取第一条线程、最多 6 帧 | 多线程未展示；栈帧没有分页；切换栈帧后用缓存作用域，没有懒加载 |
| 控制 | 继续/步过/步入/步出/停止 | 后端有 `pause`，前端没有按钮；没有重启；没有暂停时输入/求值 |
| 张量 | 按类型字符串猜 | `type` 含 `tensor` 才画 tensor 卡；没有 shape/dtype/device；长张量没有采样/轴导航 |
| 运行时画布 | 栈帧卡 + 变量卡 + `contains` 边 | 没有函数/栈帧区域；变量和函数是平级卡片；没有赋值/读取/迭代边；没有循环轨道；差异只闪一下 |
| 静态三视图 | 总览/结构/数据 | 三种视图缺少图例和视觉语法，用户看不出区别；静态/运行时只靠虚线区分 |

## 一、调试能力追平

### P0：先把“能查、能算、能停”补齐

| 能力 | 宿主 | UI | 验收判据 |
|---|---|---|---|
| 变量分页/展开 | `debug.variables` 增加 `start/count/filter`；返回 `hasMore`、总数、`named/indexed`；不再一次抓完整棵树 | 每个容器卡/树节点有“加载更多”；长数组显示首尾窗口和省略号；显示总项数 | 10,000 项数组首屏不全量卡死；能看到 `[0..9] … [9990..9999]`；加载下一页后画面更新；未加载项明确标未采集 |
| Watch/求值 | 新增 `debug.evaluate`（expression、frameId、context）；结果带代际，旧停点回包丢弃；能力按适配器返回 | 变量面板增加监视区；输入表达式、每停点刷新、错误行内显示 | 加 `len(nums)`、`nums[-1]`、`tensor.shape`；停点变化后值更新；坏表达式显示错误；未授权求值前按钮不可用 |
| 调试控制台/REPL | 复用 evaluate；区分输出与求值结果 | 控制台输入框、历史、错误 | 输入 `nums`、`len(nums)` 可在当前栈帧求值；结果不写回源码/画布事实 |
| 断点类型 | `setBreakpoints` 传 `condition`、`hitCondition`、`logMessage`；支持运行中重下发 | 断点列表/编辑器右键设置条件、命中次数、日志消息；禁用原因可见 | `i == 5` 只在成立时停；日志断点只输出不停止；命中次数生效；运行中改断点后下一次停点生效 |
| 异常断点 | 读取/设置异常过滤器；展示异常信息 | 断点面板异常选项；停止原因徽标 | 未捕获异常按配置停下并显示异常类型/消息；关闭后继续 |
| 改变量 | 新增 `debug.setVariable`；变量引用只在当前停点有效 | 变量值内联编辑；失败显示适配器错误 | 把 `x` 从 1 改成 42，下一次停点读到 42；旧停点回包被拒 |
| 暂停/重启 | 暴露 `debug.pause`；`debug.restart` 以同一程序/配置重新走原生确认 | 顶栏暂停、重启按钮 | 长循环运行中可暂停；重启清空旧帧/旧句柄并重新授权；旧回包不污染新会话 |
| 线程/栈 | 返回全部线程和栈帧分页；按需加载 scopes | 线程分组、帧分页、切换帧刷新变量 | 多线程各显示状态；100 层栈可翻页；切换帧后变量属于该帧 |
| 控制台/事件 | 输出、异常、模块事件有界展示 | 控制台分类与清空 | 输出不撑爆 DOM；异常和普通输出可区分 |

### P1：适配器支持的 VSCode 能力

- 函数断点、数据断点、内联值、悬停求值、复制值、改变量后的格式化：**以 `initialize` capability 为准**；不支持就禁用并给出原因。
- 变量分组（`Locals/Globals/Closure`）、特殊变量过滤、排序、搜索。
- 多线程全量展示、线程切换、暂停所有线程。
- 张量/框架对象：见下一节；元数据求值单独授权。
- 自动记录/回放与 Watch 结合：每帧保存 watch 结果，时间线可回看。

“VSCode 所有功能”按能力矩阵验收；**不以按钮存在代替适配器真实支持**，也不把未实现项藏起来。

## 二、运行时画布 v2

### 1. 函数/栈帧就是一张大方框

- **`FrameContainer` 不是抽象概念，就是一张大方框**：标题（函数名、`source:line`、调用深度、状态）写在框的上沿，变量卡、临时值、循环轨道都放在框里。
- 调用栈的 caller/callee 用框套框或上下堆叠表示；默认只完整展开当前帧，其他帧折叠成一个标题条，避免深层递归把画布撑爆。
- 静态函数卡在运行时变成同一个大方框的背景；同一函数的多次调用用深度/调用序号区分，不把 `variablesReference` 当对象身份。
- 验收：截图里变量卡必须在某个函数框内部；切换栈帧时框高亮和内部变量一起切换；不存在漂浮在画布上的局部变量。

### 2. 变量卡与长容器

- 统一 **ValueCard**：名称、类型、值、shape/长度、变化徽标、上一帧旧值；展开/折叠、分页、“首尾窗口 + 省略号”是同一套控件。
- 长数组：显示总数与前 10/后 10，中间 `…` 可点开加载下一页；不要用固定 100 截断；张量显示 shape 与切片预览。
- Watch 行固定在画布侧边/顶部，跨帧保持；变化时高亮，不因切换视图丢失。
- 验收：10,000 项数组在卡片内可翻页；省略号可点；总数、已加载数、未加载数都可见。

### 3. 传递关系：带语义的边

边不是装饰，必须能回答“这是什么关系”：

| 边 | 来源 | 画法 |
|---|---|---|
| `传参` | 调用语句 → 形参 | 进入函数时短暂高亮 |
| `赋值/写入` | 赋值语句/当前行 → 目标变量 | 实线箭头 + `line 23 · total += value`；只在值变化时出现 |
| `读取` | 变量 → 使用它的语句/调用 | 细虚线，按需显示 |
| `产生` | 调用结果 → 接收变量 | 与赋值区分 |
| `返回` | `return` 表达式 → 调用者 | 返回帧时高亮 |
| `迭代` | 循环 → 当次迭代变量/容器 | 与循环轨道联动 |
| `调用` | caller 帧 → callee 帧 | 栈容器之间的连线 |

DAP 不直接给“赋值事件”。实现上：静态 AST 给出当前行的写入目标；相邻停点/记录帧比较值变化；两者一致才画 `writes` 边。没有 AST 证据或值未变化时不画，标签写“写入/变化”，不假装知道完整因果。

### 4. 循环是轨道，不是一堆重复卡片

- 用静态 AST 的 `for/while` 节点 + 记录帧的重复行区间，生成 **LoopTrack**：循环头、迭代序号、当前迭代、每次迭代涉及的变量值。
- 数组排序/累加等把每轮的关键变量排成一条时间轨道；当前迭代高亮，点击某轮跳回该帧。
- 回放时轨道跟着帧走；不把每一轮都画成一张新卡片。
- 验收：冒泡排序 fixture 能看到 4 轮迭代、当前轮、`i/j/swapped` 每轮值；回放滑块和轨道当前段一致。

### 5. 张量与框架对象

- `TensorCard`：shape、dtype、device、采样预览、轴导航；大张量只取边角/切片，显示省略号。
- 元数据来源分两级：先从 DAP 变量树/repr 能确定的部分提取；不能确定时显示“shape 未知”；用户点“读取张量元数据”后，才用 `evaluate` 读取 `shape/dtype/device`，该操作纳入授权。
- 不假设框架一定存在；numpy/PyTorch 通过鸭子类型适配；没有安装或求值失败要显示原因。
- 验收：numpy 2×3 和 PyTorch tensor fixture 显示 shape/dtype；无元数据时明确未知；不伪造 shape。

### 6. 静态三视图与基础控件规范化

- 建一套 `CardSpec`：module/class/function/parameter/variable/container/loop/call/external 各有固定形状、颜色、边框、标题格式；静态卡片带 `STATIC` 徽标，运行时带 `LIVE/FRAME` 徽标，手绘用纸卡。
- 三视图不只换过滤，还要换说明：总览显示“文件符号关系”、结构显示“类/函数内部”、数据显示“数据与容器”；画布角落固定图例，解释颜色/形状/边。
- 静态卡片虚线 + 浅色，运行时实线 + 高亮；同一实体的静态/运行时卡片用同一配色，避免用户重新认。
- 验收：不读标题也能区分三个视图和静态/运行时；图例可开关；用户能说出每种颜色/形状代表什么。

### 7. 步进与回放的传递动画

- 步进/继续到新帧时：变化变量卡脉冲高亮，显示上一帧旧值；从赋值语句/调用点到变量的边短暂加粗；调用/返回帧容器之间连线。
- 回放只播放已采集帧，明确标“回放”，不暗示重新执行目标。
- 可开关图层：数据流、调用、循环、Watch；放大后保留图例和当前帧信息。

## 三、数据模型增量

- `ValueSnapshot`：增加 `childCount`、`namedVariables`、`indexedVariables`、`hasMore`、`childrenLoaded`、`page`；`children` 变成按需加载的结果，不在启动时递归抓完。
- `CapabilitySet`：增加 `conditionalBreakpoints`、`hitConditionalBreakpoints`、`logPoints`、`exceptionBreakpoints`、`restart`、`terminate`、`setExpression` 等；全部从适配器能力归一化。
- `WatchExpression`：表达式、启用状态、结果、错误、代际；结果只属于当前 stopEpoch，不写进 Trace 事实。
- `FrameRegion`：帧容器的位置/尺寸/父帧；`CanvasNode` 增加 `frameId`；画布在卡片下面画区域背景。
- `CanvasEdge`：保留现有种类，新增 `writes/reads` 的运行时标签/证据字段；赋值边必须带“静态 AST + 值变化”证据说明。
- `VariableHistory`：由帧序列派生（变量路径 → 每帧值），供 Watch 行、循环轨道、变化边使用，不存 DAP 句柄。
- `TensorMetadata`：shape/dtype/device/preview/sample 坐标；来源标记 `variables` 或 `evaluate-authorized`。

## 四、实施顺序

0. 本文与反馈落档（现在）。
1. **P0a 变量与求值**：懒加载变量树、分页/省略号、Watch/REPL、求值授权与代际校验。
2. **P0b 断点与控制**：条件/日志/命中/异常断点、setVariable、暂停/重启、线程/栈分页、调试控制台。
3. **P1 运行数据模型**：变量历史、赋值边证据、循环轨道、张量元数据适配。
4. **P2 画布 v2**：函数框（大方框）、ValueCard、语义边、LoopTrack、图例/视觉语法、步进/回放动画；卡片尺寸/分页/画布上限按 [canvas-card-spec.md](canvas-card-spec.md) 执行。
5. **语言适配器**：js-debug、GDB、java-debug；每种单独验收。

## 五、边界

- DAP 停点之外没有持续变量流；Watch 只在停点/记录帧更新，不承诺任意时刻的“实时值”。
- 赋值/读取边是静态 AST + 快照差异的推断，不是 DAP 原生的因果事件；证据不足时不画。
- 适配器不提供的能力（数据断点、部分格式化、内存读写）显示不可用，不用前端假数据补齐。
- 前端整体视觉改版仍按主人安排后置；本设计只定义调试与画布核心语义。
- 本轮先做调试与运行时数据模型，C/C++/Java 调试不在同一批。
