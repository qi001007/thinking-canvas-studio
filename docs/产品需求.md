# 产品需求

更新：2026-10-23。当前交付是基础契约和可测试核心，尚非产品 MVP。

## 用户要解决的问题

编写算法函数时，同时理解容器、张量、引用关系和函数调用带来的状态变化。减少反复手动画出已有运行数据的时间，同时保留没有运行代码时自由思考的手绘模式。

## 核心体验

| 场景 | 期望行为 | 边界 |
|---|---|---|
| 手绘 | 新建画布、数据卡片、标注、连线、记录步骤、只读回看 | 手绘数据由用户编辑，是独立事实源 |
| 编辑 | Monaco 编辑代码，保留 familiar 字体、选区、补全和快捷键 | 没执行时不宣称获得真实变量/内存 |
| 单步调试 | 断点、继续、暂停、步入/步过/步出；同步变量表、调用栈、执行行、画布 | 首先做 Python，按适配器能力控制操作 |
| 自动画布 | 容器/结构体/引用/栈帧/堆块被选择性投影；变化高亮、稳定布局 | 简单标量默认留表；不画每个细节 |
| 时间线 | 保存实际采集的暂停快照、回看差异、回到当前 | 回看不等于逆向执行；两次停点之间未知 |
| 语言扩展 | Python、C/C++、TS/JS、Java 的同一套编辑/调试交互 | 每种语言单独验收；不承诺全部语言与能力一致 |
| 本地数据 | 项目、代码、画板、注释、跟踪记录分开管理；本地原子保存 | 无账号、无云、无遥测，导出跟踪由用户主动选择 |

## 交付分期

- Phase 0（本轮）：源码契约、架构与目录、headless 核心、host 边界、单测、spike 计划。
- Phase 1（下一轮）：真实 Monaco/WebView2、bridge、debugpy、GDB 和语言依赖实验；此阶段是取证，不铺完整产品。
- MVP：Python 编辑与调试闭环 + 手绘画布 + 暂停快照可视化 + 本地文件；先允许单会话、全停语义。
- 首版语言覆盖里程碑：分别补齐 C/C++、TS/JS、Java 的最小垂直闭环；全部过关才叫“四语言首版”。
- 后续：Loaded Scripts、可选 Memory、Disassembly、Inline Values、增强引用采集、CPU 张量视图、受控连续步进播放、多线程 UI。
- 暂不做：完整 VSCode workbench/扩展市场、所有内存分配追踪、自动运行每次键入、通用 GPU 内核/显存追踪、时间旅行调试器、远程/云调试。

## 不可妥协的验收

1. 运行前确认目标、参数、工作目录、适配器和预算。缺少真实进程监管时拒绝运行。
2. 继续运行后旧句柄失效；晚回包不能污染新停点或新选帧。
3. 部分采集、未展开、优化掉、不可读、无能力、错误均可区分；禁止伪造完整内存。
4. 手绘存储不被调试快照覆盖；回看历史不会重新请求旧 DAP 句柄。
5. 编辑焦点下不触发画布单字母快捷键；切模式/选帧保持合法选择、布局和滚动状态。
6. 美学沿用 legacy：纸色、蓝色、卡片、检查器、时间线；说明放帮助层，常驻内容克制。
